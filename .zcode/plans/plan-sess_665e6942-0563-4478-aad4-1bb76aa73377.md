## 三个调整实施计划

### 1. 故障/工单级联选择器默认选中第一个一级
**现状**：`faults/index.vue` 与 `tickets/index.vue` 的 `category_path` 初始 `[]`，级联框空着显示 placeholder「一级 → 二级 → 三级」。

**改动**（两个页面）：
- `openCreate`/`openEdit`（无分类回填时）把 `category_path` 默认设为**第一个一级分类** `[l1Categories[0].name]`
- 因 dicts 异步加载，需在 `dicts` 数据到达后补默认：监听字典加载完成，若 `category_path` 为空则填第一个一级（编辑有历史分类的仍回填历史路径，不受影响）
- placeholder「一级 → 二级 → 三级」保留（仅 clearable 清空后出现），默认选中即不再显示

### 2. VPN接入故障三级去掉政务端
**现状**：`seed_fault_categories.py` 的 `VPN接入故障` 三级含「政务网VPN隧道断开」「政务移动端VPN接入失败」；生产已播种这些记录。

**改动**：
- 种子树 `VPN接入故障` 三级改为：`SSL VPN客户端连接报错 / 登录后无法访问内网资源 / 虚拟IP冲突 / 隧道建立后无流量 / 加密证书过期`（去掉两项政务）
- `clean_fault_categories()` 新增：删除生产已存在的「政务网VPN隧道断开」「政务移动端VPN接入失败」三级（先置空 Fault/Ticket 的 `fault_category_level3` 引用再删记录）
- 测试更新 VPN 相关断言（如有）

### 3. 严重级别选项改为业务影响四级 + 历史数据迁移
**现状**：`utils/permission.py` `SEVERITY_LEVELS = ['P1-紧急','P2-高','P3-中','P4-低']`；生产可能已有旧值。

**改动**：
- `utils/permission.py`：`SEVERITY_LEVELS = ['紧急故障', '严重故障', '一般故障', '轻微故障']`
- 前端自动跟随（`/api/dicts/tickets` 复用 SEVERITY_LEVELS，表单下拉/列表渲染取 `severity_levels`）
- **历史数据迁移**：新增幂等迁移函数（放 `scripts/seed_fault_categories.py` 或 app.py init_db 种子区）——`UPDATE tickets SET severity_level = CASE ... END` 映射旧值（P1-紧急→紧急故障、P2-高→严重故障、P3-中→一般故障、P4-低→轻微故障），仅命中旧值、幂等
- 测试：severity 断言改用新值
