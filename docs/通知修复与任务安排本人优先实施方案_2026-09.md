## 5. 备份与回退

### 5.1 备份分层

| 层 | 内容 | 手段 |
|---|---|---|
| 数据 | PG 全库 | `sudo bash scripts/backup.sh <APP_DIR>`（dump + 同时间戳 meta） |
| 密钥/配置/文件 | `.secret.key`、`.env`、reports/uploads/static/uploads | 同上 meta 包 |
| 代码 | 基线 `2d5563d4` | 本地 git 历史 + 回退 bundle |
| 前端 | `static/app`（本次会变更） | update.sh 自动留 `static/app.previous` |
| 队列快照 | `notification_events/deliveries/worker_states` | 发布前只读导出，修复前后对账 |

**顺序铁律：备份是发布流程的第一步。** 发布当天最先执行配对备份；未完成校验与外带前，不停 worker、不执行 update.sh、不向生产写入任何变更（scp 发布包只写入 `backups/` 目录，可在备份完成后进行）。

发布前必须：配对备份 → `pg_restore --list` / `tar -tzf` 校验 → 记录 SHA256 → 外带本机（meta 含密钥，需加密保管）。

### 5.2 发布包（5 件套，update.sh 强校验）

1. `itsm-update.bundle`（master）
2. `itsm-update.bundle.sha256`
3. `vue-dist-manual.zip`（同 commit 前端构建）
4. `vue-dist-manual.zip.sha256`
5. `itsm-release-manifest.txt`（`commit=<40位SHA>`、`bundle_sha256`、`vue_sha256`）

> 本次含前端变更，必须重新构建前端；manifest 的 commit 必须等于 bundle 应用后的 HEAD，否则 update.sh 直接 FATAL。

### 5.3 回退分层

| 层 | 操作 | 数据影响 |
|---|---|---|
| L0 止损 | `systemctl stop itsm-notifications` | 队列保留 |
| L1 代码回退（首选） | `git reset --hard 2d5563d4` → `systemctl restart itsm`；旧代码带 bug，worker 保持停止 | 零数据丢失 |
| L2 前端回退 | `static/app.previous` 还原为 `static/app` | 无 |
| L3 数据/密钥回退 | `scripts/rollback.sh <APP_DIR> backups/itsm_pg_<发布前ts>.dump` | 丢失备份点后全部业务数据，需书面确认 |
| L4 整机恢复 | 按 `docs/recovery-drill-2026-08-21.md` | 同 L3 |

注意事项：
- `rollback.sh` 会先停 `itsm` 并 **disable `itsm-notifications`**，回退后需人工重新 enable；
- L3 为 `pg_restore --clean` 整库重建，恢复后校验 readyz、alembic 版本与代码匹配（本次无迁移）；
- 回退到旧代码后不要再启用 worker（bug 仍在）。
