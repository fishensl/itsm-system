# 客户群通知第一期操作与发布说明

> 历史第一期说明：已由 [完整拓展交付说明](notification-expansion-delivery.md) 取代。下面描述第一期阶段的行为，不作为当前部署依据。

## 使用

1. 管理员在客户列表点击“通知设置”；其他人员须显式授予 `customer:notify` 并具备该客户数据范围。
2. 核对机器人属于本客户群。保存 Webhook、启用开关；地址不回显，留空保留，解绑清空。保存不会自动发送测试。
3. 点击“发送测试”并确认会向真实群发送；本地未保存修改时禁止测试。核对群内消息。
4. 查看最近 50 条记录。“接口已接受”不代表客户已读；“结果未确认”可能已发送，不自动重试。“处理中/待核对”可能是进程中断，需要人工核查。

## 自动发送范围

- 工单受理、派单、审核通过：发送工单编号，不转发内部标题、描述、处置正文。
- 巡检创建时已安排工程师、编辑时变更工程师：发送任务编号。
- 巡检开始、首次提交现场结束、审核确认：发送任务编号及结构化实施时间。
- 审核退回原因仅沿用内部通知；重提不重复现场结束，不改变实施时间。
- 一般进展、商务、安全、备份事件、任意文件与链接均不发客户群。

当前采用较保守的编号与时间模板。工程师、地点、公开摘要、客户进展编辑器、改期取消通知尚未接入，后续需先定义可公开字段，不能直接转发已有自由文本。

## 安全与运行限制

- 外网配置、启停、解绑和测试要求账号 MFA 操作验证；凭据信封使用 `customer.notify.credential.update`，沿用系统配置的兼容/强制策略。
- 客户绑定与内部、其他客户机器人冲突时拒绝。不同机器人可能位于同一个群，仍需人工核对成员和群用途。
- 默认无绑定、关闭。群通知使用已有服务器出站网络；离线安装不代表可以离线发送。
- 第一阶段提交业务后同步投递，8 秒请求超时可能增加响应耗时。业务已提交但尚未记录通知时进程退出，可能丢消息；第二期 Outbox 解决此窗口。
- 发送前检查绑定版本与启停；已经开始的网络请求无法因解绑撤回。解绑成功不表示能撤回已发送消息。
- 绑定版本保留，解绑不会删除投递历史；记录不保存正文、URL、凭据和原始异常。近期查询限制 50 条，周期清理和分页在后续通知中心阶段完善。
- 测试操作、绑定与解绑有审计。发送失败不应被解释为业务提交失败，不自动重放历史事件。
