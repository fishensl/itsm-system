# ITSM 生产迁移与恢复手册

> 面向"新服务器部署 / 换机 / 灾难恢复"的操作手册。与 `scripts/backup.sh`（备份）、
> `scripts/restore.sh`（整机恢复）、`scripts/rollback.sh`（紧急回滚）、`scripts/pg-migrate.sh`（SQLite→PG）配套。
> 当前生产（172.16.123.124 /home/itsm-system_20260614）为 PostgreSQL。

---

## 0. 备份产物一览

| 产物 | 来源 | 内容 | 用途 |
|---|---|---|---|
| `itsm_pg_<ts>.dump` | backup.sh（PG 模式） | pg_dump -Fc 自定义格式整库 | DB 恢复 |
| `itsm_meta_<ts>.tar.gz` | backup.sh（PG 模式） | `.secret.key` + `.env` + `reports/` + `uploads/` + `static/uploads/` | 密钥/配置/文件恢复 |
| `itsm_full_<ts>.tar.gz` | backup.sh（SQLite 模式） | `instance/itsm.db` + 密钥 + .env + 文件目录（整包） | SQLite 整机恢复 |
| `itsm_backup_<ts>.zip` | Web「系统→备份」导出 | 全量业务数据（data.json + 密钥 + 文件，可选密码加密） | Web 内导入覆盖恢复 / 跨机数据迁移 |

**备份三件套原则**：数据库 + `.secret.key`（解密设备/AI 密码必需）+ 业务文件目录（reports/uploads）必须同时备份；丢密钥 = 全部密文不可解。

## 2. 换机/新服务器部署（PG→PG 或 SQLite→SQLite）

### 2.1 新机准备
```bash
# 安装依赖（Ubuntu）
sudo apt-get update && sudo apt-get install -y postgresql python3 python3-venv git unzip
# 代码（离线：先 scp itsm-update.bundle 到新机）
git clone /path/to/itsm-update.bundle itsm-system   # 或用 git bundle 应用
cd itsm-system && python3 -m venv venv && venv/bin/pip install -r requirements.txt
# .env：从 meta 包还原或手工创建（ITSM_SECRET_KEY / ITSM_DATABASE_URI / ITSM_ENV=production）
```

### 2.2 恢复
```bash
# 旧机全量备份（停机窗口内执行）
sudo bash scripts/backup.sh /home/itsm-system_20260614
scp backups/itsm_pg_*.dump backups/itsm_meta_*.tar.gz root@新机:/home/itsm-system_20260614/backups/

# 新机整机恢复（自动：停服→pg_restore→密钥/文件→启动）
sudo bash scripts/restore.sh /home/itsm-system_20260614 backups/itsm_pg_<ts>.dump

# 或 SQLite 模式
sudo bash scripts/restore.sh /home/itsm-system_20260614 backups/itsm_full_<ts>.tar.gz
```

### 2.3 验证
- `systemctl is-active itsm` = active；`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:5000/login` = 302
- 浏览器登录 → 抽查客户/设备/巡检报告下载/拓扑图 → **设备密码查看**（验证密钥已还原）
- `venv/bin/python -c "from app import create_app,init_db; init_db(create_app())"`（schema 对齐 head + seed 幂等）

## 3. SQLite → PostgreSQL 升级（原库迁移）

```bash
# 迁移前体检（只读）
sudo bash scripts/pg-check.sh
# 执行迁移（9 步：导出→建库→导入→切 URI→重启；自动备份 sqlite_shuttle_*.tar.gz + 全量 zip）
sudo bash scripts/pg-migrate.sh
# 如需回退 PG→SQLite
sudo bash scripts/pg-rollback.sh
```

迁移要求：PG 首次 upgrade 前必须有 `cb9d639a430f`（类型修复）与 `e5f6a7b8c9d0`（FK DEFERRABLE）两个迁移（已满足）。迁移含密钥还原（`restore_secret_key=True`）。

## 4. 灾难恢复 / 紧急回滚

| 场景 | 操作 |
|---|---|
| 发布后数据异常 | `sudo bash scripts/rollback.sh <app> backups/itsm_pg_<ts>.dump`（pg_restore 重建）+ 代码切回旧 tag + 前端还原 static/app.bak |
| 整机损坏 | 新机装代码 + `.env` → `restore.sh`（见 §2） |
| 仅误操作数据 | Web「系统→备份→导入」覆盖恢复（`data_io.perform_import`，含 sha256 校验 + schema 漂移检查） |

---

## 5. 关键注意

- **零网络服务器**：依赖均需离线包（`itsm-update.bundle` + `vue-dist-manual.zip` 成对），pip 安装依赖服务器已有包或内网源。
- **密钥备份**：`.secret.key` 与数据库必须同时备份（backup.sh 已含）；轮换用 `scripts/rotate_secret_key.py`。
- **PG 序列**：Web 导入（perform_import）已自动 `setval` 重置序列；脚本级 pg_restore --clean 无此问题。
- **跨库迁移**：生产已是 PG，本手册的 SQLite 流程仅适用于其他 SQLite 部署。
