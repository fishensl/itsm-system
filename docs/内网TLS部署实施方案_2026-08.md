# ITSM 内网 TLS 部署实施方案（172.16.123.124）

> 状态：待实施；本文不代表生产环境已变更。  
> 基线：2026-08-30，生产入口目前使用 `http://172.16.123.124:5000`。  
> 目标：Windows/Edge 用户通过受信任的内网域名访问 HTTPS；Gunicorn 不再直接暴露；登录、MFA、设备密码和附件全程由 TLS 保护。  
> 关联方案：`docs/工单故障处置时间与敏感凭据安全整合实施方案_2026-08.md`。

## 1. 推荐架构

```text
Windows / Edge
  │  https://itsm.<现有内网DNS域>:443
  │  TLS 1.2 / 1.3
  ▼
Nginx（172.16.123.124）
  │  只在本机转发，并覆盖代理头
  ▼
Gunicorn 127.0.0.1:8000
  │
  ├─ PostgreSQL 127.0.0.1:5432
  └─ /opt/itsm 运行时文件
```

核心边界：

1. 用户只访问规范域名，不再把 `172.16.123.124:5000` 作为正式入口。
2. Nginx 是唯一外部入口，监听 443；80 和旧 5000 只在迁移期执行固定域名跳转。
3. Gunicorn 从 `0.0.0.0:5000` 改到 `127.0.0.1:8000`，远端无法绕过 Nginx。
4. Flask 只信任一层 Nginx 的代理头；客户端传入的 `X-Forwarded-*` 由 Nginx覆盖。
5. 第一阶段所有静态文件仍经 Flask/Nginx 反代，不直接对 `/static/` 做统一 alias，避免绕过 `/static/uploads/*` 登录鉴权。

## 2. 当前代码必须同时调整的安全点

| 位置 | 当前情况 | TLS 上线前调整 |
| --- | --- | --- |
| `scripts/itsm.service:12` | Gunicorn 监听 `0.0.0.0:5000` | 改为 `127.0.0.1:8000` |
| `app.py:202-203` | 无条件信任 1 层 `X-Forwarded-Proto/Host` | 增加可配置代理层数；生产为 1，开发直连为 0；同时启用 `x_for=1` |
| `utils/access_control.py:33-42` | 直接读取用户可伪造的 `X-Real-IP/X-Forwarded-For` | 改为读取经 `ProxyFix` 校正后的 `request.remote_addr` |
| `config.py:105` | 所有响应都写一年 HSTS | HSTS 改由 Nginx在客户端全部信任证书后分阶段开启 |
| `scripts/lib-release.sh:5`、`scripts/rollback.sh:122` | 健康检查写死 `127.0.0.1:5000` | 改为环境变量 `ITSM_INTERNAL_READY_URL`，默认 `http://127.0.0.1:8000/readyz` |
| `utils/transport_security.py:51-55` | 可信内网设备凭据允许 HTTP | TLS 验收后删除该例外，敏感 HTTP 一律拒绝 |
| `.env.example:7` | `ITSM_FORCE_HTTPS=0` | TLS 灰度通过后生产设为 `1` |

不能只安装 Nginx 证书而保留公网可达的 `0.0.0.0:5000`。当前应用会依据 `X-Forwarded-Proto` 判断安全协议；若后端端口仍可直连，伪造代理头会破坏该安全边界。

## 3. 域名与证书

### 3.1 规范域名

在现有单位内网 DNS 域中创建：

```text
itsm.<现有内网DNS域>  A  172.16.123.124
```

要求：

- 使用现有 AD/DNS 管理的真实命名空间，不新建 `.local` 等临时后缀。
- 正式书签、通知链接、二维码统一使用规范域名。
- 证书 SAN 必须包含 `DNS:itsm.<现有内网DNS域>`。
- 如果迁移期确实要求直接访问 `https://172.16.123.124`，证书还必须包含 `IP:172.16.123.124`；仅把 IP 写入 CN 无效。推荐仍统一跳转到域名。

### 3.2 证书来源优先级

1. **已有 AD CS：首选。**申请“Web Server/服务器身份验证”证书，私钥在 Linux 服务器生成，CA 只签 CSR。
2. **已有单位内部 CA：复用。**要求提供完整 root/intermediate/leaf 链和可用的吊销机制。
3. **没有 CA：建立独立离线根 CA + 在线签发 CA。**根 CA 私钥不得放在 ITSM 服务器；不要给每台服务器单独制作无法集中轮换的自签名叶子证书。
4. **拥有公共域名且允许 DNS-01：**可使用公开受信任证书配合内网分离 DNS，减少客户端根证书分发；是否采用由网络和合规策略决定。

建议参数：RSA 3072 + SHA-256，EKU 为 Server Authentication，有效期 1 年，提前 30 天告警与续签。证书私钥放置：

```text
/etc/itsm/tls/fullchain.pem   root:root 0644
/etc/itsm/tls/privkey.pem     root:root 0600
```

Nginx 主进程以 root 启动后读取私钥，worker 不需要对目录开放写权限。

### 3.3 Windows/Edge 信任分发

有 AD 时创建独立 GPO，仅链接到需要访问 ITSM 的计算机 OU：

```text
计算机配置
  → 策略
  → Windows 设置
  → 安全设置
  → 公钥策略
  → 受信任的根证书颁发机构
```

导入根 CA；如有中间 CA，同时导入“中间证书颁发机构”。客户端执行 `gpupdate /force` 后在 `certlm.msc` 验证。Windows Edge 会继续信任本机/企业安装的本地根证书。

无 AD 的少量测试终端，可由管理员临时执行：

```powershell
certutil -addstore -f Root .\itsm-root-ca.cer
```

这只用于测试或受管脚本分发；不得要求普通用户点击忽略证书警告。

## 4. Nginx 配置模板

将下列 `<现有内网DNS域>` 替换为实际域名后保存到 `/etc/nginx/sites-available/itsm.conf`：

```nginx
upstream itsm_backend {
    server 127.0.0.1:8000;
    keepalive 16;
}

# 规范 HTTP 入口只做 HTTPS 跳转
server {
    listen 80;
    listen [::]:80;
    server_name itsm.<现有内网DNS域>;
    return 308 https://itsm.<现有内网DNS域>$request_uri;
}

# 旧地址迁移期兼容；观察期结束后删除并关闭 5000
server {
    listen 5000;
    server_name _;
    return 308 https://itsm.<现有内网DNS域>$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name itsm.<现有内网DNS域>;

    ssl_certificate     /etc/itsm/tls/fullchain.pem;
    ssl_certificate_key /etc/itsm/tls/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:ITSM_TLS:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    client_max_body_size 100m;

    location / {
        proxy_pass http://itsm_backend;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port 443;

        proxy_connect_timeout 5s;
        proxy_send_timeout 120s;
        proxy_read_timeout 120s;
    }
}
```

说明：

- `X-Forwarded-For` 使用 `$remote_addr` 而不是追加客户端传来的原始头，当前架构只有一层边缘 Nginx，可直接覆盖伪造值。
- 暂不配置 `location /static/ { alias ...; }`。如果后续要卸载静态文件，只能单独开放 `/static/app/`、`/static/vendor/` 等确认公开的目录，`/static/uploads/` 必须继续经过 Flask 鉴权。
- 初次切换不立即写 HSTS。客户端信任覆盖率确认后再按第 7 节逐级开启。

启用前检查：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 5. 应用与 systemd 配置

### 5.1 Gunicorn

`scripts/itsm.service` 目标值：

```ini
ExecStart=/opt/itsm/venv/bin/gunicorn --no-control-socket --bind 127.0.0.1:8000 --workers 4 --timeout 120 wsgi:app
```

生产 `.env` 增加：

```dotenv
ITSM_TRUSTED_PROXY_COUNT=1
ITSM_TRUSTED_HOSTS=itsm.<现有内网DNS域>,127.0.0.1,localhost
ITSM_INTERNAL_READY_URL=http://127.0.0.1:8000/readyz
```

TLS 首次灰度时先保持：

```dotenv
ITSM_FORCE_HTTPS=0
```

确认 Edge、MFA、上传、设备密码和回调全部通过后再改为：

```dotenv
ITSM_FORCE_HTTPS=1
```

### 5.2 代理与真实 IP

应用侧调整为：

- `ITSM_TRUSTED_PROXY_COUNT=0` 时不启用 `ProxyFix`，用于本地直连开发。
- 生产值为 1 时启用 `x_for=1, x_proto=1, x_host=1`。
- `client_ip()` 只读 `request.remote_addr`，由 `ProxyFix` 负责可信代理链解析。
- Nginx 未就绪前不得把生产代理层数设为 1。
- Flask `TRUSTED_HOSTS` 与 Nginx `server_name` 同时限制 Host，拒绝未知域名。

### 5.3 Cookie 与 CSRF

启用 `ITSM_FORCE_HTTPS=1` 后：

- 登录 session 自动带 `Secure; HttpOnly; SameSite=Lax`。
- `csrf_token` 保持非 HttpOnly，供 Vue 写入 `X-CSRFToken`，但在 HTTPS 请求上带 `Secure`。
- Cookie 不设置 Domain，保持 host-only；从 IP 切到域名后自然建立新会话，用户需要重新登录一次，这是预期行为。

## 6. 防火墙

最终策略：

| 端口 | 来源 | 用途 |
| --- | --- | --- |
| 443/tcp | 已批准内网/VPN 网段 | 正式访问 |
| 80/tcp | 已批准内网/VPN 网段 | 跳转到 HTTPS，可长期保留 |
| 5000/tcp | 迁移期内网，最终关闭 | 旧书签跳转 |
| 8000/tcp | 仅 127.0.0.1 | Gunicorn，不对网络开放 |
| 5432/tcp | 仅本机/明确数据库网段 | PostgreSQL |

切换后必须从另一台内网机器验证 `172.16.123.124:8000` 和后端旧端口不可连接。仅改 UFW 而继续监听 `0.0.0.0` 不算完成。

## 7. 分阶段切换

### 阶段 T0：只读预检

- 确认 Linux 发行版、Nginx 版本、当前防火墙、端口占用、内部 DNS 域、AD CS/内部 CA、客户端 OU。
- 盘点通知、二维码、书签和脚本中所有 `http://172.16.123.124:5000`。
- 生成完整配对备份并验证 `pg_restore --list`；保存当前 systemd、Nginx、`.env` 配置副本。

### 阶段 T1：证书和客户端信任

- 创建 DNS 记录并签发服务器证书。
- 先向 2–3 台测试终端分发根/中间 CA。
- 用 Edge 验证无证书告警、证书 SAN 正确、链完整、有效期和吊销信息正常。

### 阶段 T2：代码与后端收口

- 完成第 2 节代码调整并跑全量后端、前端和发布脚本测试。
- Gunicorn 切至 `127.0.0.1:8000`；Nginx 开启 443、80 和临时 5000 跳转。
- 保持 `ITSM_FORCE_HTTPS=0` 做第一轮 HTTPS smoke，避免证书/代理问题与应用门禁同时发生。

### 阶段 T3：小范围灰度

- 测试管理员、普通运维、viewer 三类角色。
- 完成用户名密码→MFA→工作台、登出重登、首次改密、设备密码设置/查看、100 MB 内上传、下载、工单/巡检流程。
- 旧 URL 必须保留 path 和 query 并跳转到规范域名。

### 阶段 T4：强制 HTTPS

- 全体受管终端收到证书策略后设 `ITSM_FORCE_HTTPS=1`。
- 删除设备凭据可信内网 HTTP 例外。
- HSTS 按 `300 秒 → 1 天 → 30 天 → 180 天` 逐级增加；至少经过一个完整业务周期后再提升。
- 内网域名不使用 `preload`，初期不加 `includeSubDomains`。

### 阶段 T5：关闭旧入口

- 观察 14–30 天确认旧端口无有效访问后，删除 Nginx 5000 跳转并关闭防火墙 5000。
- 更新 README、生产迁移手册、部署脚本输出、通知和二维码，全部只显示 HTTPS 域名。

## 8. 验收命令和用例

服务端：

```bash
sudo nginx -t
sudo systemctl is-active nginx itsm
ss -lntp | grep -E ':80|:443|:5000|:8000'
openssl s_client -connect 172.16.123.124:443 -servername itsm.<现有内网DNS域> -showcerts
curl --cacert /path/to/root-ca.pem https://itsm.<现有内网DNS域>/healthz
curl -fsS http://127.0.0.1:8000/readyz
```

远端 Windows：

```powershell
Resolve-DnsName itsm.<现有内网DNS域>
Test-NetConnection itsm.<现有内网DNS域> -Port 443
Test-NetConnection 172.16.123.124 -Port 8000
curl.exe -I http://172.16.123.124:5000/app/login
curl.exe -I https://itsm.<现有内网DNS域>/app/login
```

验收标准：

- Edge 地址栏无证书警告；证书名称与规范域名一致。
- 登录密码和 MFA 后不会跳回登录页；Edge、内嵌浏览器均通过。
- Session Cookie 有 Secure/HttpOnly/SameSite；CSRF 写操作正常。
- 从远端不能直连 8000；伪造 `X-Forwarded-Proto: https` 没有后端直连通道。
- 未登录访问 `/static/uploads/*` 仍为 404；Nginx 不绕过 Flask 守卫。
- 设备密码设置/查看在 HTTPS 可用，HTTP 返回拒绝或固定跳转。
- 访问控制审计记录的客户端 IP 是真实终端地址，不是 `127.0.0.1`，也不能由请求头伪造。

## 9. 回滚原则

1. 证书或客户端信任失败：保持 Gunicorn 仅监听回环，回退 Nginx 到上一份有效证书/配置；不得重新暴露 `0.0.0.0:5000`。
2. `ITSM_FORCE_HTTPS=1` 导致业务异常：可临时关闭该开关，但外部访问仍必须经过 Nginx HTTPS；不能恢复设备密码 HTTP 明文通道。
3. 代理真实 IP 异常：回退应用提交并保持 Nginx 覆盖代理头；确认访问控制后再继续。
4. HSTS 只在完成灰度后逐步增加，避免证书错误时客户端长时间无法回退；回滚时不能依赖立即清除已缓存 HSTS。
5. 每次改动保留 `/etc/nginx`、systemd、`.env` 配置快照；数据库无 schema 变化，但仍执行发布配对备份。

## 10. 实施前需要落实的三个现场值

本文模板可以先进入代码准备；真正签证书和切换生产前，只需要现场确认：

1. 规范域名：`itsm.<实际内网DNS域>`。
2. 证书来源：现有 AD CS、其他内部 CA，还是新建内部 CA。
3. 允许访问 443 的准确内网/VPN CIDR 列表。

这三个值必须来自现网，不能在代码或证书里猜测。
